# msgspec Domain Modeling

This project's binding data-modeling rules live in `docs/v3_specification/10_Domain_and_Data/02_DTOS_AND_ENUMS.md` (the master DTO/enum catalog) and `docs/v3_specification/16_Engineering_Standards/03_CODING_STANDARDS.md` §4 (Cross-boundary data structures). This skill distills both into the rules you apply every time you touch a `models.py`.

## The one-sentence rule

**Every data structure that crosses a module boundary is a `msgspec.Struct` declared `frozen=True, kw_only=True, gc=False`.** No exceptions, no "just this once" dataclass, no `dict[str, Any]`.

## The mandatory struct shape

```python
import msgspec


class BenchmarkResult(msgspec.Struct, frozen=True, kw_only=True, gc=False):
    result_id: int
    run_id: int
    provider_id: str
    model_name: str
    duration_ms: int
    status: ResultStatus
    error_message: str | None = None
```

Each of the three flags is load-bearing — never drop one, never reorder construction to skip it:

| Flag | Why it is mandatory |
|---|---|
| `frozen=True` | The struct is immutable, gets a structural `__eq__`, and is safe to share across threads with no locking. This matters concretely in this codebase: `BenchmarkResult` rows cross from worker threads to the dispatcher thread to the GUI thread via the event bus — an unfrozen struct would be a data race waiting to happen. |
| `kw_only=True` | Every construction site is self-documenting. Adding or reordering a field never silently breaks a positional-argument call site somewhere else in the codebase. |
| `gc=False` | The struct is exempt from cyclic garbage-collection scans. This is safe specifically because DTOs in this codebase never participate in reference cycles — they are pure value records, not object graphs with back-references. |

Field-level constraints are expressed with `Annotated` + `msgspec.Meta`, validated automatically at decode/construction time — a violated constraint raises immediately, which is exactly what you want for a programmer error caught at the boundary, not three call frames later.

```python
from typing import Annotated

RetryCount = Annotated[int, msgspec.Meta(ge=1, le=10)]
ProviderIdStr = Annotated[str, msgspec.Meta(pattern=r"^[a-z][a-z0-9_]*$", max_length=64)]
```

### Real constrained types from this codebase (`02_DTOS_AND_ENUMS.md` §3)

These are not hypothetical — they are the actual reusable types declared once and referenced everywhere a field needs them. Reach for one of these before inventing a new `Annotated` alias:

```python
# Internal UUID4 identifiers — auto-generated by the owning store on insert.
ProviderIdStr   = Annotated[str, msgspec.Meta(
    pattern=r"^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$",
    max_length=36,
)]
ModelNameStr    = Annotated[str, msgspec.Meta(min_length=1, max_length=256)]
TaskIdStr       = Annotated[str, msgspec.Meta(min_length=1, max_length=128)]

NonNegativeFloat = Annotated[float, msgspec.Meta(ge=0.0)]   # matches a DB CHECK (>= 0)
PositiveFloat    = Annotated[float, msgspec.Meta(gt=0.0)]   # matches a DB CHECK (> 0)
NonEmptyStr      = Annotated[str, msgspec.Meta(min_length=1)]

# A 0.0-1.0 bounded score - the canonical "constrained float field" example.
CosineScore      = Annotated[float, msgspec.Meta(ge=0.0, le=1.0)]
CosineThreshold  = Annotated[float, msgspec.Meta(ge=0.0, le=1.0)]

# A bounded positive-int field - the canonical "constrained int field" example.
RetryCount       = Annotated[int, msgspec.Meta(ge=0, le=10)]
TimeoutSeconds   = Annotated[int, msgspec.Meta(ge=1, le=3600)]
PositiveInt      = Annotated[int, msgspec.Meta(ge=1)]
NonNegativeInt   = Annotated[int, msgspec.Meta(ge=0)]
DurationMs       = Annotated[int, msgspec.Meta(ge=0)]
RepeatCount      = Annotated[int, msgspec.Meta(ge=1, le=50)]
```

A constraint violation at construction time is a **programmer error** (`ValidationError`, a `ProgrammerError` leaf) — never an expected runtime condition. It is not how you validate user input; see the `error-taxonomy-and-redaction` skill for that boundary.

## `StrEnum` for every closed value domain

Every fixed, named set of values that gets persisted, exported, or compared against raw text is a `StrEnum`. The member value is the lowercase/snake_case string stored in SQLite and emitted in YAML/exports.

```python
from enum import StrEnum


class RunMode(StrEnum):
    SYNTHETIC = "synthetic"
    TASKS     = "tasks"
    GRADED    = "graded"


class Verdict(StrEnum):
    PASS = "pass"
    FAIL = "fail"
```

Rules that matter in practice:

- **Always write `.value` explicitly** when an enum member is serialized, persisted, compared to raw text, or embedded in a format string. Never rely on implicit `str` coercion of an enum member inside an f-string — that is a known mypy/format-string inconsistency this project deliberately avoids.
- `Literal[...]` is reserved for tiny contract-local unions that never cross a persistence or export boundary. A plain `enum.Enum` (not `StrEnum`) is for fixed named choices whose value is never serialized — rare in this codebase, since almost everything here eventually hits SQLite or an export.
- A binary outcome like `Verdict` is deliberately **exactly two members** (`PASS`/`FAIL`) with no `UNKNOWN` — "pending" is represented by the field being `None`, not by a third enum member. Don't add a synthetic "unknown" member to an enum when the absence of a value already means that; use `X | None` instead.

## Timestamps

Every timestamp that crosses a module boundary is an ISO-8601 UTC string (`str`), not a `datetime`, not a float epoch. The persistence layer stores it verbatim.

```python
type Iso8601Utc = str   # e.g. "2026-05-22T14:53:09Z"
```

## `@dataclass` — the one narrow exception

`@dataclass` is permitted **only** for a type strictly private to a single module's `_internal/` package that never crosses a module boundary. The moment a value needs to be returned from `api.py`, passed to another module, put on the event bus, or persisted, it is a `msgspec.Struct`, full stop.

```python
# OK - lives entirely inside backend/csv_export/_internal/writer.py,
# never imported by anything outside that file.
@dataclass(slots=True)
class _ColumnWidthAccumulator:
    column_index: int
    max_width: int
```

If you find yourself importing a `@dataclass` from another module's `_internal/`, that import is already forbidden by the layering rules (see `three-layer-architecture`) — which is exactly the enforcement mechanism that keeps this exception narrow.

## Never `dict[str, Any]` for structured data

If you catch yourself writing `dict[str, Any]`, `dict[str, object]`, or a loosely-typed `TypedDict` substitute for anything with a known, fixed shape — stop and declare a `msgspec.Struct` instead. This is a hard ban, not a style preference: `dict[str, Any]` defeats `mypy --strict`, defeats `icontract` postconditions, and silently accepts typos in keys that a Struct would catch at construction.

## Worked example: wrong vs. right

**Wrong** — a `@dataclass` masquerading as a cross-boundary DTO:

```python
# WRONG - crosses from backend/persistence into backend/benchmark_pipeline,
# but is mutable, has no kw_only enforcement, and isn't gc-exempt.
from dataclasses import dataclass


@dataclass
class ModelCapabilityRecord:
    provider_id: str
    model_name: str
    capability: str          # should be the ModelCapability StrEnum
    supported: int
    last_observed_at: str
    observed_via: str        # should be the CapabilitySource StrEnum
    detail: str = None       # wrong: str cannot default to None under mypy --strict
```

Problems: mutable (unsafe to share across the dispatcher/worker/GUI threads), positional construction is allowed (a field reorder silently breaks callers), participates in GC scans for no reason, and uses bare `str` where a `StrEnum` exists.

**Right** — the actual project-shape struct, matching `02_DTOS_AND_ENUMS.md` §5.3:

```python
import msgspec

from ollama_llm_bench.backend.domain.enums import CapabilitySource, ModelCapability
from ollama_llm_bench.backend.domain.types import Iso8601Utc, ModelNameStr, ProviderIdStr


class ModelCapabilityRecord(msgspec.Struct, frozen=True, kw_only=True, gc=False):
    provider_id: ProviderIdStr
    model_name: ModelNameStr
    capability: ModelCapability
    supported: int                       # tri-state: 1 yes | 0 no | -1 unknown
    last_observed_at: Iso8601Utc
    observed_via: CapabilitySource
    detail: str | None = None
```

This version is immutable, keyword-only, GC-exempt, uses the project's constrained type aliases, and uses `StrEnum` members instead of bare strings for both `capability` and `observed_via`.

## Persistence note — relational, not blob

Domain data in this project is stored **fully relationally** in SQLite — a struct is never persisted as an opaque JSON/blob column. The tagged-union forward-compatibility pattern (`tag=`, `tag_field=` on `msgspec.Struct`) exists only for a struct serialized to disk **as a unit outside the relational tables** (a future on-disk cache or export payload) — it does not apply to the SQLite domain tables, which evolve through additive structural migration steps instead. Don't reach for tagged unions when you're just adding a column to a persisted table.

## Quick checklist before you commit a new/changed DTO

- [ ] `class Name(msgspec.Struct, frozen=True, kw_only=True, gc=False)` — all three flags present.
- [ ] Every closed value domain is a `StrEnum`, not a bare `str`.
- [ ] Every constrained numeric/string field uses (or adds to) the shared `Annotated[..., msgspec.Meta(...)]` aliases, not an ad-hoc inline constraint.
- [ ] Every timestamp field is `Iso8601Utc` (`str`), not `datetime`.
- [ ] No `dict[str, Any]` anywhere in the signature.
- [ ] If this is a `@dataclass`, it lives in a `_internal/` package and never crosses a boundary — otherwise it must be a Struct.
- [ ] Every enum member's `.value` is used explicitly wherever it touches serialization, persistence, or an f-string.
