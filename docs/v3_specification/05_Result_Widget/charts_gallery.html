A chart shows its kind-specific empty_state_message, never blank axes. Prev/next stays enabled so the user can move to a populated chart.
Filter bar — shared by every chart. Five global multi-select chips — Models, Status, Verdict, Category, Difficulty — narrow the working result set; the active chart's aggregator re-computes on the narrowed set. Each chart adds its own per-chart options after the chips (unit, aggregation, outlier toggle, axis scale, ungraded-handling toggles, metric switches, heatmap cell-value switch).

Mode availability. Charts 1–4, 8, and 12 are offered in every run mode; charts 5, 6, 7, 9, 10, and 11 are offered only for GRADED because they need a verdict or a Cosine Score. A hidden chart never appears in the chart-kind dropdown nor in prev/next navigation.

Drill-down and export. Clicking a chart element switches to the Details tab with a matching filter applied. The footer exports the current chart as PNG or SVG at 2400 x 1600, with the active theme's palette. The per-run, per-chart-kind filter and option state persists with the run.

Two gallery-wide conventions. Low-sample marking — any aggregate computed from fewer than eval.min_sample_size (default 5) completed rows is drawn with a 45° hatch fill and annotated with its n (e.g. n=3); the group is still shown but flagged low-confidence (13_CHART_AGGREGATORS.md §6.5a). Because n is a property of a model's completed-row count, the same model is hatched consistently across every per-model aggregate chart. Count-only charts (success/failed, verdict counts) and per-row charts (scatter) carry no hatch because they are not rate aggregates; the heatmap expresses the same idea per cell as a no data cell. Empty state — when a chart has no usable data it renders its kind-specific empty_state_message inside a dashed placeholder (never blank axes), and prev/next navigation stays enabled. Each chart note above lists its exact empty-state message.
